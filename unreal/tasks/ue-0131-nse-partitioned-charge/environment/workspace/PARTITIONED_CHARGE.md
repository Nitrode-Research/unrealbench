# Partitioned charge commands

`FChargeCommand` (in the state script header) describes one partitioned charge command: `ChargeInput` is the direction or button to charge, `RequiredFrames` the total held frames needed, `MaxGapFrames` the longest interruption kept, `LifetimeFrames` the longest age, counted from the first held frame, at which a charge can still activate, `Trigger` either `Release` of the charged input or `Press` of `TriggerInput`. Input bitmasks are the engine's `EInputFlags` and combine direction and button flags; the neutral flag is never part of a command. Directions are facing-relative, so `INP_Left` is back and `INP_Right` is forward.

`UState::ChargeCommands` holds the commands of a state in a player's primary state machine; subordinate state machines are out of scope. The state is entered when one of its ordinary `InputConditionLists` passes or when one of its charge commands activates. State priority is unchanged: when several states are satisfied on the same frame, the one added to the state machine last is checked first.

`FNSE004Battle` is a neutral authoring fixture in `Fixtures/`. It creates a real game state with two human players in a synthetic world; `Player` (side 0) receives `Input1` and `Dummy` (side 1) receives `Input2`. `Player` starts facing right and `Dummy` facing left, so at the start `Dummy`'s back is the physical right. `AddMove(RecoveryFrames, ChargeCommands, InputConditionLists, Side)` registers a move for that side before the first `Step` and returns its index; indices count separately per side. A started move keeps its player busy for the next `RecoveryFrames - 1` unfrozen frames and the player idles again on the `RecoveryFrames`-th unfrozen frame after the entry frame; frozen frames do not count toward recovery, and the recovery still owed is part of the battle state that `Save` and `Restore` carry. `SetMoveEnterable(Move, Enterable, Side)` makes a move fail or pass the engine's scripted state condition, one of the ordinary gates a state must pass to be entered; moves start enterable and the flag is fixture bookkeeping, not battle state. `Step(Input1, Input2)` advances one engine battle frame. `Sides[Side].Entries` lists every move start of that player as `(BattleState.FrameNumber, move index)`; `FrameNumber` starts at 0, advances on every step including frozen ones, is rolled back by `Restore` and is not reset by `ResetRound`. `CurrentMove(Side)` is the move in progress or `INDEX_NONE`. `Sides[Side].ClockFrames` counts the steps on which that player was not frozen and changes only inside `Step`, so a step that leaves it unchanged was a frozen frame for that player.

`Hitstop(N, Side)` sets the engine's hitstop counter on that player exactly as a hit would; the engine decrements it before checking, so `N` yields `N - 1` frozen frames, for that player only. `SuperFreeze(N)` starts a super freeze called by `Dummy`, which freezes `Player` for `N` frames and leaves `Dummy` running. `SwitchSides()` swaps the players' positions and calls the engine's `FaceOpponent` on both. `ResetRound()` runs the engine's `RoundInit`, which puts both players back at their start positions facing each other (`Player` right, `Dummy` left), and restores the fixture's timer settings. `Save()` and `Restore(Snapshot)` wrap `SaveGameState` and `LoadGameState`. `Entries` and `ClockFrames` are fixture bookkeeping and are never rolled back or reset.
