# Local replay interface

The game instance provides `BeginReplaySession`, `PlayReplayFromBP`, `SeekReplay(double)`, `TakeOverReplay(int32)`, `TakeOverReplayAt(double,int32)`, `PauseReplay(bool)`, `FinishReplayBranch` and `AdvanceReplay(ANightSkyGameState*)`. Positions count simulated input pairs. Side 0 is P1; side 1 is P2. `TakeOverReplay` uses the current position; `TakeOverReplayAt` validates both arguments before changing the session. Replay eligibility follows the compatibility and asset rules regardless of the mode in which it was recorded; an otherwise valid zero-length source has position 0. Rejections return false and report `ReplayStatus::Rejected`. Successful seek/takeover calls return with their destination state available.

`AdvanceReplay` advances one battle frame with local inputs supplied by the selected player's controller. Past the source's length the unselected side contributes no input at all, the zero value `INP_None`; `INP_Neutral` is a distinct named flag and is not it. After takeover, rematch and training-reset commands are stripped from both sides' effective inputs, including inputs still supplied by the source, and never appear in the recorded branch pairs. `ANightSkyGameState::bPauseGame` also pauses replay. Observe position, owner and completion through `GetReplayPosition`, `GetReplayOwner` and `IsReplayComplete`. `GetWorkingBranch` and `GetReplaySource` expose replay initialization, decoded input pairs, `LengthInFrames`, `TakeoverFrame` and `TakeoverSide`. Their storage strategy is unrestricted.

`GetSavedBranchSlot` identifies the completed branch; `GetSavedReplaySlots` lists saved replays. `ReplaySlotPrefix` selects a save namespace and defaults to `REPLAY`. Save identities are opaque, unique and reopenable through ordinary playback. Existing saves remain intact: saving never replaces one, and `FinishReplayBranch` rejects rather than overwrite when the namespace has no unused identity left. `FinishReplayBranch` is idempotent: repeated calls remain successful while saving only once.

Restored destination presentation includes the collision debug view when `ANightSkyGameState::bViewCollision` is set.

`AAudioManager::CommonAudioObserver` is an optional native observer of common one-shot audio. `PlayCommon` and `StopCommon` are the engine's common-channel presentation calls and report to it, so started and stopped playback is observable without an audio device. Like the common-effect renderer it carries no replay policy; deciding whether to present at all remains the caller's.

The native sample content in `Fixtures/ReplayFixture.h` supplies persistent character/stage assets and ordinary battle controls. Directional inputs move; A attacks; B launches a projectile. Its authored damage, timing, collision geometry and presentation assets are available in the source. `AReplayFixtureGameMode` selects the sample battle and controller on the engine Entry map.

Common one-shot effects may use `AParticleManager::CommonParticleRenderer`, an optional native renderer receiving the real common-effect spawn request and world transform. `UpdateParticles` advances it; `ClearCommonParticles` clears transient presentation. An unhandled request falls back to the existing asset renderer. The supplied HLSL integration fixture uses this path and needs no visual-graph authoring. Preserve normal effect emission, lifetime, and resumption while suppressing skipped effects. A seek to a time before an existing one-shot was born, or after it expired, must not retain that effect. A no-op seek must not restart or erase a live effect.

The optional native common-effect renderer uses logical frame time, independently of owner hitstop. A forward seek advances effects already alive at its start by the elapsed logical time, while suppressing new effects from skipped frames. Rewinding discards one-shot presentation from the old timeline; historical one-shots encountered during reconstruction stay suppressed. No-op seeks preserve existing one-shot presentation. Starting a valid fresh replay session clears old native one-shots; a rejected start leaves existing effects unchanged. Persistent destination visuals remain subject to the ordinary destination-restoration requirement.
