# Swept projectile authoring

`ABattleObject::ConfigureSweptProjectile(Enabled, Piercing, ContactLimit)` configures swept contacts for the current projectile activation. The default is disabled. Limits are positive, with invalid values clamped to one. `GetSweptContactLimit()` reports the effective limit for the current configuration; the authored value is retained exactly, so an implementation must not impose an internal maximum. Changing configuration does not clear accepted-target history. `SetContactOrderKey(Key)` assigns a nonnegative authored target key. Keep keys distinct and stable during an activation.

A target activation lasts from activation until deactivation. Reactivating a target starts a new activation eligible for a later contact from a still-active projectile. Frames, hitstop, teleportation and hurtbox changes do not create a new activation. Ordering keys determine ties only and do not define target identity.

`TeleportBattlePosition(X,Y)` sets integer battle position and marks discontinuous travel for the current frame. Call it from gameplay state execution when teleporting. Further movement during that frame remains endpoint-only. Ordinary position updates are continuous. `AddBattleObject`, `DeactivateObject`, `SaveGameState` and `LoadGameState` retain their engine meanings.

Geometry follows the engine's integer transform. Positive configured sizes truncate when divided by two. Left facing negates the local X offset and rotation angle. Normalize authored angles modulo a full turn before the engine's table lookup. Each sine/cosine multiplication divides separately by 1000 with truncation toward zero, before rotation components and world translation are combined. These compatibility rules can collapse a positive-size box into a segment or point. The engine's sine/cosine table remains the source of its coefficients. Collision visualization is diagnostic; integer collision geometry determines contacts.

`FNSE005Battle` provides neutral native authoring support. It creates real battle actors and collision data, and `Step(Input1,Input2)` advances the engine battle frame. `Boxes(Object,Boxes)` assigns collision assets. `Move(Object,X,Y)` schedules continuous movement. `Teleport(Object,X,Y,MoveAfterTeleportX)` schedules discontinuous movement. `Spawn` and `SpawnTarget` use normal pooled battle-object creation.

The fixture exposes `Game`, `Projectile`, `Targets`, `Trace`, and `Script(Object)`. Script fields `PendingMoveX/Y`, `bSpawnPending`, `bSpawnTargetPending`, and `SpawnX` schedule authored actions during state execution. `OnContactAction` uses `ENSE005ContactAction`: `None`, `DeactivateProjectile`, `DisableHit`, or `MakeTargetInvulnerable`. The last action grants `ChangeTarget` strike invulnerability. Event trace entries use the authored key for hit/block callbacks and `-key-1` for receive callbacks.
