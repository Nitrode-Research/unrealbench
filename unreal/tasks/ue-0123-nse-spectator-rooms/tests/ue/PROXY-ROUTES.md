# Per-endpoint UDP forwarding

The measured campaign waited 60.64 seconds for a restarted client socket. The old adapter reused one server-facing UDP source port and changed a mutable frontend peer when a replacement process sent a packet. This made a distinct client endpoint appear to reuse the previous transport identity and could also redirect queued old responses to the replacement. No implementation behavior or private transport format is used to repair that adapter defect. The observed delay is a reason to profile the correction, not a claimed measured speedup.

Each distinct frontend endpoint now receives an immutable route generation and fresh upstream UDP socket. The selector records the originating route for downstream packets; all queued packet records retain that route generation. Delivery resolves the original route's exact socket and frontend. Old endpoints and their sockets remain available until proxy shutdown, including for delayed upstream traffic, delayed responses and late old-endpoint datagrams. Creating another route never changes an existing one. Packets log route generation and both endpoints. No configured fault is inferred from closing a route.

Finite fault counters and held/overtaking packets are separate for each route and direction, with an episode identifier attached to queued witnesses. A new endpoint cannot supply the overtaking datagram for another route's held packet. The approved bidirectional burst episodes, repeated combat schedule, membership/authentication/nonce/stale-event assertions and all deadlines remain.

Two new real-UDP tests cover old queued response ownership, distinct server-facing source ports, delayed old upstream source identity, late old-endpoint routing, and interleaved route-local held/overtaking witnesses. All 14 host tests and Python compilation pass. The campaign-approved-freeze.zip remains the immutable earlier 11-test campaign baseline; this route repair is a separate delta. A protected engine rerun is required to measure startup and campaign cost.

An independent review found that an unconfigured late downstream packet could create an untouched upstream witness for an old route. Witness creation now occurs only for the packet's actual configured direction. Completion separately requires every configured direction on the latest route at configuration time and on newly opened routes; absence cannot pass vacuously. Real partial witnesses on old routes still must finish. The new UDP regression proves complete-new-route → late-old-downstream stays complete, then genuine old upstream loss makes it incomplete until that old route's own held/overtaking packets finish. The bidirectional regression explicitly rejects completion before any downstream witness exists.
